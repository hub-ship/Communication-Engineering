第一章 操作系统概述

1.1 什么是操作系统

操作系统（Operating System, OS）是管理计算机硬件与软件资源、为用户提供交互接口的系统软件。它是计算机系统的"内核"，位于硬件与应用之间。

1.2 操作系统的五大功能

功能说明举例
进程管理进程的创建、调度、销毁task / ps / kill
内存管理内存分配、回收、虚拟内存malloc / 分页 / swap
文件系统文件的存储、组织、保护ext4 / NTFS / FAT32
设备管理外部设备的驱动与调度键盘 / 网卡 / 磁盘
用户接口提供命令行(CLI)与图形(GUI)bash / GNOME

1.3 操作系统的发展史

  • 无操作系统（1940s-50s早期）：直接操作硬件，ENIAC时代
  • 批处理系统：把任务攒一批交给计算机串行执行
  • 多道程序系统：内存中同时放多道程序，CPU切换提升利用率
  • 分时系统：多个用户通过终端共享一台机器（UNIX雏形）
  • 实时系统：RTOS，通信基站、工业控制常用
  • 现代OS：微内核（QNX/HarmonyOS）、宏内核（Linux）、混合（Windows/macOS）
💡 通信工程视角 通信系统中很多设备运行的是实时操作系统：基站用Linux + RT补丁，核心交换设备用VXWorks，嵌入式终端常用FreeRTOS/RT-Thread。理解OS内核对学习通信协议栈实现大有裨益。

1.4 操作系统的特征

  • 并发：多个事件在同一时间间隔内交替进行
  • 共享：资源供多个并发进程共同使用（互斥/同时）
  • 虚拟：把一个物理实体映射成多个逻辑实体（如虚拟内存）
  • 异步：进程执行走走停停，速度不可预知但结果可重现
🌱 小白详解 · 新手怎么看懂本章

🔍 通俗理解：操作系统 = 硬件的"大管家"：管理 CPU（调度）、内存（分配回收）、文件、设备，同时给应用程序提供好用的接口（系统调用）。有了它，多个程序才能在一台机器上"和平共处"。

📝 例子/口诀：分时系统的贡献：CPU 切时间片轮流伺候各终端用户，"一人一机"的错觉由此而来——Unix 因此称霸。

⚠️ 易错点：① 系统调用 vs 库函数：printf 是库函数，底层最终才调用 write 系统调用；② 并发 ≠ 并行：单核时间片切换叫并发，多核同时执行才叫并行；③ 用户态/内核态切换是有代价的（现场保存/恢复），频繁切换会拖慢系统。

⭐ 学习重点：OS 四大管理功能各一句话、系统调用的作用、用户态与内核态的切换时机（系统调用/中断/异常）。

第二章 进程与线程

2.1 进程的概念

进程（Process）是程序在某数据集合上的一次动态执行过程，是OS进行资源分配和调度的基本单位。

进程 = 程序代码 + 当前活动（PC、寄存器、堆栈等） + 数据段 + 资源。

PCB（Process Control Block）是内核为每个进程维护的数据结构，保存进程状态、PID、寄存器值、内存指针、打开的文件描述符等。

2.2 进程的状态转换

新建 (New) → 就绪 (Ready) ⇄ 运行 (Running) → 阻塞 (Blocked) → 退出 (Exit)
状态含义
新建 New进程刚被创建，PCB未初始化完
就绪 Ready已具备运行条件，等待CPU调度
运行 Running正在CPU上执行
阻塞 Blocked等待某事件（如I/O完成）而无法运行
退出 Exit进程执行结束，资源待回收

2.3 进程控制块 PCB

Linux 中 PCB 由 task_struct 结构体表示（include/linux/sched.h），关键字段：

c
struct task_struct {
    pid_t               pid;            // 进程ID
    pid_t               tgid;           // 线程组ID（主线程同PID）
    volatile long       state;          // 进程状态
    struct mm_struct   *mm;             // 内存描述符
    struct files_struct *files;         // 打开的文件描述符
    struct signal_struct *signal;       // 信号相关
    struct thread_struct thread;        // CPU寄存器上下文
    int                 prio;           // 动态优先级
    int                 static_prio;    // 静态优先级
    /* …… 还有很多字段 …… */
};

2.4 线程的概念

线程（Thread）是进程内的执行单元，是CPU调度的基本单位。一个进程可以包含多个线程，它们共享进程的地址空间、文件描述符、堆等资源，但各自拥有独立的栈和寄存器。

对比项进程线程
资源拥有独立地址空间共享所属进程资源
切换开销大（页表、缓存都要换）小（同进程内切换）
通信方式IPC（管道、共享内存、socket）直接共享全局变量
健壮性一个崩溃不影响其他线程崩溃可能拖垮进程

🌱 小白详解 · 新手怎么看懂本章

🔍 通俗理解：进程 = 程序的一次执行过程（活的），程序 = 磁盘上的死文件。PCB 是进程的"户口本"（PID、状态、优先级、寄存器现场），创建进程本质就是创建 PCB。

📝 例子/口诀：五状态模型背图：新建→就绪→运行→（等待事件）阻塞→（事件到来）就绪→运行→终止。就绪等的是 CPU，阻塞等的是事件（如 IO 完成）——两者绝对不能混。

⚠️ 易错点：① 线程 = 进程内的执行流，共享进程的地址空间和资源，只私有栈和寄存器——所以线程切换比进程切换快得多；② IPC 四种方式对比：管道（父子进程）、消息队列（内核中转）、共享内存（最快，需配信号量同步）、信号（异步通知）；③ "进程与线程的区别"是出现率最高的简答题，从资源、切换开销、通信方式三个维度答。

⭐ 学习重点：五状态转换图（画箭头标触发条件，必考）、进程与线程全方位对比、各 IPC 方式的适用场景。

第三章 CPU调度算法

3.1 调度层次

  • 高级调度（作业调度）：决定把外存上哪些作业调入内存
  • 中级调度（内存调度）：决定把哪些进程挂起到磁盘、对换
  • 低级调度（进程调度）：决定就绪队列中哪个进程获得CPU

3.2 主要算法对比

算法思想优点缺点
FCFS 先来先服务按到达顺序简单公平平均等待时间长
SJF 短作业优先优先跑时间短的平均周转最优长作业饥饿
时间片轮转 RR轮流执行，固定时间片响应快、交互友好上下文切换开销
优先级调度高优先级先跑灵活低优先级饥饿
多级反馈队列 MLFQ动态调整优先级综合最优实现复杂

3.3 时间片轮转示例

假设时间片 q = 4，到达与运行时间如下：

进程到达时间服务时间
P107
P224
P341

执行甘特图：

[0–4] P1 → [4–5] P3 → [5–8] P2 → [8–11] P1

平均等待时间 = (0 + 4 + 1) / 3 ≈ 1.67

💡 Linux 的 CFS 调度器 Linux 默认调度器 CFS（Completely Fair Scheduler）基于"虚拟运行时间" vruntime，红黑树维护，运行时间越少越优先。本质就是加权公平的 RR + 多级反馈。
🌱 小白详解 · 新手怎么看懂本章

🔍 通俗理解：CPU 调度 = 决定就绪队列里谁下一个上 CPU。评价维度：周转时间（到达→完成）、带权周转（周转/服务时间）、等待时间、响应时间。

📝 例子/口诀：算法一览：FCFS 先来先服务（简单但对短作业不公平）、SJF 短作业优先（平均周转最优但长作业可能饿死）、RR 时间片轮转（交互体验好）、优先级（会饿，需老化 aging 补救）、多级反馈队列（动态综合，最接近真实系统）。

⚠️ 易错点：① 时间片太大退化成 FCFS、太小则上下文切换开销吞掉 CPU——适中才是美；② SJF 的可抢占版本叫 SRTF，才是理论最优；③ 计算题套路：列表格按时间轴逐个推演，注意新进程到达时是否抢占。

⭐ 学习重点：给定作业表计算各算法的完成时间/周转/带权周转——必考大题，务必动手画甘特图。

第四章 进程同步与死锁

4.1 临界区问题

一段访问共享资源的代码称为临界区。解决临界区问题需满足：

  • 互斥：一次只有一个进程在临界区
  • 前进：临界区外的进程不能阻止其他进程进入
  • 有限等待：进入请求不能无限等待

4.2 同步工具

工具原理使用场景
互斥锁 mutex同一时刻只能一个线程持有保护临界区
读写锁 rwlock读共享、写互斥读多写少
信号量 semaphore计数器，经典 PV 操作生产者消费者
条件变量 cond阻塞等待某条件成立事件通知
自旋锁 spinlock忙等待不阻塞中断/短临界区

4.3 生产者-消费者模型代码

c
#include 
#include 
#include 

#define N 5

int  buffer[N];
int   in = 0, out = 0, count = 0;
pthread_mutex_t mtx = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t  not_full  = PTHREAD_COND_INITIALIZER;
pthread_cond_t  not_empty = PTHREAD_COND_INITIALIZER;

void put(int x) {
    pthread_mutex_lock(&mtx);
    while (count == N)                        // 满则阻塞
        pthread_cond_wait(¬_full, &mtx);
    buffer[in] = x; in = (in+1) % N; count++;
    pthread_cond_signal(¬_empty);
    pthread_mutex_unlock(&mtx);
}

int get(void) {
    pthread_mutex_lock(&mtx);
    while (count == 0)                        // 空则阻塞
        pthread_cond_wait(¬_empty, &mtx);
    int x = buffer[out]; out = (out+1) % N; count--;
    pthread_cond_signal(¬_full);
    pthread_mutex_unlock(&mtx);
    return x;
}

4.4 死锁的四个必要条件

  1. 互斥：资源一次只允许一个进程使用
  2. 占有并等待：持有资源又申请新资源
  3. 不可剥夺：资源只能主动释放，不能被抢
  4. 循环等待：进程间形成环路等待
✅ 死锁处理策略
  • 预防：破坏四个条件之一（如一次性申请所有资源）
  • 避免：银行家算法（检测是否进入不安全状态）
  • 检测：资源分配图 + 等待图环路检测
  • 解除：剥夺资源、回滚进程

4.5 银行家算法伪代码

text
// 安全性算法
Work = Available
Finish[i] = false for all i

存在 i:
    Finish[i] == false 且 Need[i] ≤ Work
    Work = Work + Allocation[i]
    Finish[i] = true
    goto 开始

如果所有 Finish[i] == true 则安全
🌱 小白详解 · 新手怎么看懂本章

🔍 通俗理解：多个进程竞争共享资源需要"排队规则"——这就是同步。信号量是万能工具：P 操作（wait）申请资源可能阻塞、V 操作（signal）释放资源必唤醒等待者。

📝 例子/口诀：死锁四条件：互斥、持有并等待、不可剥夺、循环等待——同时成立才会死锁，破坏任意一个即可预防。银行家算法思想：借钱前先验证"借出后大家都能顺利还清"才借。

⚠️ 易错点：① 经典死锁场景——生产者消费者：两个 P 操作顺序颠倒就死锁，口诀"对多个互斥资源的 P 要按统一顺序"；② 信号量初值的含义：资源数量（互斥信号量初值 1，同步信号量初值 0 或资源数）；③ 死锁的三个层次：预防（静态破坏条件）> 避免（银行家动态检查）> 检测恢复（发生后处理）。

⭐ 学习重点：生产者-消费者代码填空（信号量定义+P/V 位置，高频题型）、银行家算法的安全性序列判断、死锁四条件及对策。

第五章 内存管理

5.1 内存管理的目标

  • 地址保护：进程只能访问自己的地址空间
  • 地址共享：让多进程共享物理页（如共享库）
  • 空间扩展：虚拟地址空间大于物理内存
  • 存储抽象：给进程一个干净的"独占"视图

5.2 连续分配

  • 单一连续：早期单用户，简单但浪费
  • 固定分区：内存在启动时划好若干区
  • 动态分区：按需分配，会产生外部碎片，用首次适配/最佳适配等策略

5.3 分页存储管理（核心）

分页把进程的逻辑地址空间和物理内存都划分为大小相等的"页/页框"。

逻辑地址 = 页号(P) + 页内偏移(W) 物理地址 = 页框号(f) × 页大小 + W

页表（Page Table）记录页号→页框号的映射。为了加速，引入了TLB（快表）作为缓存。

5.4 多级页表与缺页中断

32位系统4KB页：1M 个页条目，单级页表要4MB。Linux 采用二级页表，节省内存。

如果访问的页不在内存中，会触发缺页中断（Page Fault），OS 把页从磁盘调入内存。如果内存满则按页面置换算法淘汰一页：

  • FIFO 先进先出：简单但性能不佳
  • LRU 最近最久未使用：理论最优，实现近似（Clock算法）
  • LFU 最不经常使用
  • OPT 最佳置换（理论参考，不可实现）
💡 Belady 异常 FIFO 在某些访问序列下，增加页框反而增加缺页次数（Belady Anomaly）。LRU 和 LFU 都不会发生。

5.5 段式管理

按程序的逻辑结构（代码段、数据段、堆栈段）划分。段号 + 段内偏移，便于保护与共享。

🌱 小白详解 · 新手怎么看懂本章

🔍 通俗理解：内存管理演进史就是与"碎片"斗争的历史：连续分配（外碎片）→分页（固定大小页框，内碎片小）→虚拟内存（程序可以比物理内存大，缺页时按需调入）。

📝 例子/口诀：地址换算模板：逻辑地址 = 页号 × 页大小 + 页内偏移；查页表得物理页框号，物理地址 = 页框号 × 页大小 + 页内偏移。例：页 1KB，逻辑地址 2500 → 第 2 页（2500/1024=2）偏移 452。

⚠️ 易错点：① FIFO 可能出现 Belady 异常——分配的页框变多、缺页反而变多（LRU 不会）；② 缺页 ≠ 页面失效，缺页中断处理后可以继续执行；③ 抖动（thrashing）：进程太多、内存装不下工作集，CPU 全在换页不干正事。

⭐ 学习重点：给页面访问序列算 FIFO/LRU/Optimal 的缺页次数对比（必考计算题）、逻辑地址→物理地址换算、工作集概念。

第六章 文件系统

6.1 文件的概念

文件是一组带名字的相关信息的集合。文件系统负责：

  • 创建/删除文件
  • 组织目录
  • 按名存取、保护
  • 提供一致的访问接口（open/read/write/close）

6.2 文件的逻辑结构

  • 无结构（流式）
  • 有结构（记录式，顺序/索引）
  • B+ 树索引（数据库常用）

6.3 物理结构（分配方式）

方式特点
连续分配顺序访问快，有外部碎片
链接分配消碎片，但只能顺序访问
索引分配随机访问快；可多级索引

6.4 FAT 与 inode

Linux 的 ext4、经典的 UNIX FS 都用 inode：每个文件一个 inode，记录元数据与数据块指针（12直接+1间接+2二级）。

bash

6.5 虚拟文件系统 VFS

Linux 的 VFS 层对上层应用屏蔽差异，统一提供 open/read/write/stat 接口。它把底层差异（ext4、xfs、nfs、tmpfs）通过统一的 inode_operations 等结构体呈现。

🌱 小白详解 · 新手怎么看懂本章

🔍 通俗理解：文件系统回答"数据如何在磁盘上组织与寻址"。核心角色：inode 存文件元数据（大小、权限、数据块指针），目录本质是"文件名→inode 编号"的映射表。

📝 例子/口诀：UNIX 的多级索引：inode 里直接块 + 一级间接 + 二级间接 + 三级间接指针——小文件快（直接块）、大文件能扩展（间接块），兼顾两头。

⚠️ 易错点：① inode 里没有文件名——文件名在目录项里，同一 inode 多个名字就是硬链接；软链接是独立文件、内容是路径（删原文件后软链接悬空、硬链接仍有效）；② 硬链接不能跨文件系统（inode 编号是局部的）、不能链接目录；③ EXT4 的日志先记后改，掉电后能快速恢复一致性。

⭐ 学习重点：inode 多级索引的最大文件计算题、硬链接 vs 软链接对比、文件存储三种分配方式（连续/链接/索引）优劣。

第八章 用户与权限管理

8.1 用户与组

Linux 是多用户系统。每个用户有 UID，每个用户至少属于一个主组 GID。常见配置文件：

  • /etc/passwd — 用户基本信息
  • /etc/shadow — 加密密码（仅 root 可读）
  • /etc/group — 组信息
bash
$ cat /etc/passwd
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
ubuntu:x:1000:1000:Ubuntu:/home/ubuntu:/bin/bash

字段含义：用户名:密码占位:UID:GID:描述:家目录:登录shell

8.2 权限三位一体

-rwxr-xr-- 1 root root 234 May 12 14:33 file

第一位是文件类型（-=普通 d=目录 l=链接 b/c/p/s=设备）。

后 9 位分三组：

位含义
rwx (owner)属主：读/写/执行
r-x (group)同组：读/不可写/执行
r-- (other)其他：只读

8.3 数字权限与修改

bash
chmod 755 file                  # rwxr-xr-x
chmod u+x,g-w file              # 属主加执行、同组去掉写
chown alice:dev file            # 改属主+属组
chgrp dev file                  # 仅改组
umask 022                       # 默认权限掩码：新文件 644，目录 755

# 特殊位
chmod u+s file                  # SUID：执行时拥有属主权限（如 /usr/bin/passwd）
chmod g+s dir                   # SGID：新建文件继承目录属组
chmod +t /tmp                   # Sticky：只有属主能删（/tmp 用到）

8.4 ACL 与 sudo

bash

⚠️ 安全提示
  • 密码散列在 /etc/shadow，权限 640，root 才能读
  • 不要给非运维人员 NOPASSWD: ALL，用具体命令白名单
  • chmod 777 在生产环境是危险品，按需最小原则给权限
🌱 小白详解 · 新手怎么看懂本章

🔍 通俗理解：Linux 权限三元组 rwx 分别值 4/2/1，三组对象 owner/group/others。chmod 755 = 属主可读写执行、其他人可读可执行（网站目录的标准姿势）。

📝 例子/口诀：看懂 ls -l 第一列：-rwxr-xr-- 拆成类型位 + 三组权限位，一眼判断"我是谁、我能干啥"。

⚠️ 易错点：① 目录的 x 是"能否进入目录"，r 只是"能否 ls 列出名字"——没 x 有 r 看得见进不去；② 脚本要有 x 权限才能直接 ./运行，或者用 bash xxx.sh 绕过；③ chmod 数字法（755）与符号法（u+x）要都会；chown 改属主、chgrp 改属组。

⭐ 学习重点：权限数字与符号互换、目录权限与文件权限的差异、sudo 的意义与 /etc/sudoers。

第十一章 习题与思考

一、选择题

1. 进程和线程的本质区别是？
A. 进程是动态的，线程是静态的
B. 进程是资源分配单位，线程是CPU调度单位
C. 线程共享地址空间，进程独立地址空间
D. 进程有PCB，线程没有
查看答案
B、C 均正确，但 B 是教材定义性表述，C 是结果性表述。答案：B。
2. 下列哪个调度算法不会产生 Belady 异常？

查看答案
答案：B。FIFO 是栈式算法会出现 Belady 异常；二次机会本质 FIFO。
3. /etc/shadow 文件权限是？
查看答案
-rw-r----- 即 640，属主 root，属组 shadow，仅这两者可访问。

二、简答题

Q1. 描述死锁的四个必要条件，举出一个生活化例子。
查看答案
① 互斥 ② 占有并等待 ③ 不可剥夺 ④ 循环等待。
例子：马路十字路口四辆车互不相让——每辆车占有一段路（占有并等待），且路段不能被抢（不可剥夺），四辆车之间形成循环等待（每辆车都等前面那辆让行）。
解法：交通信号灯破坏循环等待，互让规则打破占有并等待。
Q2. 为什么需要虚拟内存？
查看答案
① 让进程看到比物理内存大的地址空间（空间扩展）。
② 多进程共享物理内存，提高利用率。
③ 进程之间内存相互隔离，提供保护。
④ 与文件系统一起，支撑 fork 等高级特性（写时复制 COW）。
Q3. 硬链接和软链接的区别，举例。
查看答案
硬链接共享 inode，本质同一文件多个名字，不能跨文件系统、不能指向目录。
软链接是路径"快捷方式"，保存的是目标文件名，inode 不同，可跨文件系统，源文件删除后失效。
例：ln a.txt b.txt 硬链接；ln -s a.txt b.txt 软链接。删 a.txt 后，b.txt 还能读（硬），但 b.txt 会标红闪烁（软）。

三、计算题

Q1. 页面访问序列为：7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1，当物理页框数为 3 时，分别用 FIFO 和 LRU 计算缺页次数。
查看答案
FIFO 缺页 12 次，LRU 缺页 12 次（实际此序列两者结果相同，常见题型"页面序列 + 算法"）。
排查法：
FIFO 队列：开始[7,0,1] → 2 替换 7 → [0,1,2] → 3 替换 0 → [1,2,3] → 0 替换 1 → [2,3,0] → 4 替换 2 → [3,0,4] → 2 替换 3 → [0,4,2] → 3 替换 0 → [4,2,3] → 0 替换 4 → [2,3,0] → 3 命中 → 2 命中 → 1 替换 2 → [3,0,1] → 2 替换 3 → [0,1,2] → 0 命中 → 1 命中。
缺页 = 12。
LRU 类似追踪访问时间排序，得出 12 次。

  2. ping 网关与外网
  3. tcpdump 抓一次 HTTP 请求 tcpdump -i any -A -nn port 80
